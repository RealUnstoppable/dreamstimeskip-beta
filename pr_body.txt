💡 **What:**
- Batched DOM insertions in `js/account.js`'s `renderOrders` function using a `DocumentFragment`.
- Replaced the O(N) `merged.find()` array lookup in `js/navbar.js`'s `PRELOADED_NOTIFICATIONS` loop with an O(1) `Set` lookup (`mergedIds.has()`).

🎯 **Why:**
- Iteratively calling `listEl.appendChild(card)` inside a loop causes O(N) costly layout reflows and repaints in the browser. Using a `DocumentFragment` batches this into a single O(1) DOM update.
- Using `Array.find()` inside a `forEach` loop results in O(N²) time complexity. Using a `Set` makes the lookup O(1), improving the overall operation to O(N), which prevents CPU bottlenecking as the notification list grows.

📊 **Impact:**
- Reduces layout reflows on the account page's order history from O(N) to O(1), significantly improving render speed for users with many orders.
- Improves notification merging time complexity from O(N²) to O(N).

🔬 **Measurement:**
- Render times for the order list can be profiled using Chrome DevTools Performance tab; layout shifts and rendering time will be tangibly lower for large datasets.
