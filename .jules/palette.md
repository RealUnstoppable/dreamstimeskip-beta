## 2024-10-22 - Proper Button State Restoration
**Learning:** When creating asynchronous form submissions or handling user interactions that trigger API calls (like `handleAnswerSubmit`), the submit button is typically disabled with a loading state (e.g., "Submitting...") at the start of the process. If the restoration of the button state (`btn.disabled = false`) is only placed inside a `catch` block, the button remains stuck in a disabled loading state after a *successful* operation. This is a subtle but frustrating micro-UX bug because the user cannot interact with the button again if needed, or it simply looks broken.
**Action:** Always place UI state restoration logic (e.g., `btn.disabled = false; btn.textContent = originalText;`) inside a `finally` block. This guarantees the UI is properly reset and interactive again regardless of whether the underlying operation succeeds or fails.
