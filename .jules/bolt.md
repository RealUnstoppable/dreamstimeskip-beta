## 2024-05-24 - [Micro-UX Event Delegation]
**Learning:** In highly interactive dynamic lists like Lyrics and Spotlight search, repeated event listeners can cause huge memory bloat. Furthermore, modifying DOM instances iteratively inside functions like `renderLyrics()` can create stale closure bugs.
**Action:** Applied Event Delegation using dataset checks (`dataset.delegated = "true"`) to attach single event listeners on parent containers and check `e.target.closest()`. The listener is attached globally (e.g., inside `initHarmonyTunes`) and reads dependencies like `activeAudio` dynamically at execution time, which decreases listener bloat and runs significantly faster without stale closure issues.

## 2024-05-24 - [Massive Array Map Caching]
**Learning:** In projects parsing massive local data arrays like `librarySongs` (over 29,000 items), utility functions resolving objects using `Array.prototype.find()` can result in severe client-side execution blocking if called repetitively. A critical insight was correctly modeling Map-caching to preserve legacy duplication. Since `librarySongs` intentionally allows ID duplication, you *must* use `!_songCache.has(id)` before setting Map keys; blindly mapping will overwrite the first occurrence with the last occurrence, breaking backwards compatibility with `find()`.
**Action:** Changed O(N) lookup loops to use a lazy-initialized Map cache (O(1)) checking `has()` for identical `find()` array parity behavior. Added bounds checking via `_lastLibraryLength` to allow the cache to safely clear when dynamic arrays are appended to via client actions.
