## 2024-05-24 - [Micro-UX Event Delegation]
**Learning:** In highly interactive dynamic lists like Lyrics and Spotlight search, repeated event listeners can cause huge memory bloat. Furthermore, modifying DOM instances iteratively inside functions like `renderLyrics()` can create stale closure bugs.
**Action:** Applied Event Delegation using dataset checks (`dataset.delegated = "true"`) to attach single event listeners on parent containers and check `e.target.closest()`. The listener is attached globally (e.g., inside `initHarmonyTunes`) and reads dependencies like `activeAudio` dynamically at execution time, which decreases listener bloat and runs significantly faster without stale closure issues.

## 2024-05-18 - Avoid array length vs map size validation for cached arrays with duplicate IDs
**Learning:** The `librarySongs` array in this application contains objects with duplicate IDs (e.g., due to appending different variations or tags over time). When attempting to implement a lazy-loaded cache using a Map, using `map.size !== librarySongs.length` to check if the cache needed rebuilding failed catastrophically. The condition evaluated to true on every call because the Map collapsed duplicate keys, resulting in a size smaller than the array's length. This turned an intended O(1) optimization into an O(N) array iteration and Map allocation on every function call.
**Action:** When implementing lazy-loaded caching for large static or semi-static arrays, use a dedicated integer variable to track the array's length (e.g., `let _lastLibraryLength = -1;`) and compare against that, rather than relying on the Map's size property.
