## 2024-05-24 - [Micro-UX Event Delegation]
**Learning:** In highly interactive dynamic lists like Lyrics and Spotlight search, repeated event listeners can cause huge memory bloat. Furthermore, modifying DOM instances iteratively inside functions like `renderLyrics()` can create stale closure bugs.
**Action:** Applied Event Delegation using dataset checks (`dataset.delegated = "true"`) to attach single event listeners on parent containers and check `e.target.closest()`. The listener is attached globally (e.g., inside `initHarmonyTunes`) and reads dependencies like `activeAudio` dynamically at execution time, which decreases listener bloat and runs significantly faster without stale closure issues.

## 2024-05-24 - [O(1) Map Cache for Static Arrays]
**Learning:** When using a `Map` to cache and optimize lookups for large static arrays (e.g., `librarySongs`), using `Array.from(map.values())` in fallback search paths within frequently called functions allocates a massive new array in memory on every execution, causing severe performance and memory regressions. Iterate over the original static array directly for fallbacks instead. Also, never use `map.size !== librarySongs.length` to check for cache invalidation when the array contains duplicate IDs, as it evaluates to true on every call. Use a separate variable to track array length.
**Action:** Replaced O(N) `Array.find()` lookups with an O(1) Map cache in `getSongById`. Implemented lazy-rebuild check using `librarySongs.length !== _lastLibraryLength` and used a simple `for` loop for the fallback search. Checked `!_songCache.has(song.id)` before setting to handle duplicate IDs correctly.
