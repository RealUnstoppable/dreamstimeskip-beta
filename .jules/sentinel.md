
## 2025-02-28 - [CRITICAL] Path Traversal in Express Static File Middleware
**Vulnerability:** A path traversal vulnerability existed in `server.js` within a custom middleware block used to serve HTML files (e.g., `let html = await fs.readFile(filePath, 'utf8');`). An attacker could supply URL-encoded sequences (`%2e%2e%2f` instead of `../`) to bypass the overly simplistic regex normalization check (`path.normalize(reqPath).replace(/^(\.\.[\/\\])+/, '')`) because Express's `req.path` does not automatically decode URL-encoded slashes. This allowed reading arbitrary files on the filesystem (e.g., `/etc/passwd`).
**Learning:** `req.path` only decodes standard URL encodings but leaves encoded slashes like `%2f` intact. Standard `path.normalize()` does not prevent directory traversal if the dot-segments are hidden via URL encoding or strategically placed. The regex `/^(\.\.[\/\\])+/` is flawed because it only targets leading sequences and fails if the traversal occurs mid-path (e.g., `/app/..%2f..%2fetc/passwd`).
**Prevention:** Always use `decodeURIComponent()` wrapped in a `try-catch` block before processing the path. Check for and reject null bytes (`\0`). Strip leading slashes to prevent `path.resolve()` from evaluating the path as absolute. Enforce directory boundaries strictly by ensuring the resolved path begins exactly with the intended root directory plus a path separator (e.g., `if (!resolvedPath.startsWith(__dirname + path.sep) && resolvedPath !== __dirname)`).
