## 2024-05-24 - Path Traversal Vulnerability in Express File Server
**Vulnerability:** A local file server middleware in `server.js` attempted to prevent directory traversal by naively stripping out `../` dot-segments using a regular expression (`replace(/^(\.\.[\/\\])+/, '')`) without decoding the URL first. This allowed an attacker to bypass the filter using URL-encoded dot-segments (like `%2e%2e/%2e%2e/etc/passwd.html`).

**Learning:** `req.path` in Express does *not* automatically decode URL-encoded slashes (`%2f`) or backslashes. Relying on simple string replacement for path traversal protection is insufficient because attackers can encode payload components. Furthermore, when using `path.resolve(baseDir, reqPath)` to build the final absolute file path, if `reqPath` starts with a slash `/`, `path.resolve` treats it as an absolute path from the root directory and ignores `baseDir` entirely.

**Prevention:** To correctly mitigate path traversal in Node.js/Express, the input must first be explicitly decoded using `decodeURIComponent`. Then, reject the request if it contains a Null Byte (`\0`). To safely resolve the path against a base directory like `__dirname`, any leading slash in the decoded input must be replaced or prefixed with a dot (`.` or `./`) so `path.resolve` treats it as relative. Finally, enforce strict directory boundaries by checking if the resolved absolute path starts with `__dirname + path.sep` and is not exactly equal to `__dirname`.
